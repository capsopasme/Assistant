# 助手（Assistant）

给 **小米 13 · HyperOS 3（国行，KernelSU root）** 写的轻量手机助手：长按电源键唤起，直接说话（用
[离线语音输入（Audio Input）](https://github.com/capsopasme/audio_input) 的离线识别，不弹键盘）或打字。常用指令在本机直接执行（不联网、瞬间完成），
其余交给 DeepSeek / 智谱 GLM / Gemini 中你选定的一个，通过工具调用操作手机或回答问题。没有语音播报，没有常驻服务。

## 安装与配置

1. 安装 [Releases](https://github.com/capsopasme/Assistant/releases) 里的 APK。
2. 在 **KernelSU 管理器**里给「助手」开启超级用户（KernelSU 不会弹窗询问）。
3. 打开「助手」→ **一键配置**。它会：
   - 把本应用设为默认数字助理（`cmd role add-role-holder`）；
   - 让长按电源键唤起数字助理（`long_press_power_key=launch_google_search`），而不是小爱；
   - 把语音识别服务指向小米自带引擎，避免重启后被系统重置为小爱；
   - 允许「后台弹出界面」和「锁屏显示」（从面板打开其他应用需要）；
   - 授予通讯录和拨号权限（按姓名打电话）；
   - 关闭助理的读屏 / 截屏（每次唤起都不会截取屏幕）；
   - 授予麦克风、修改系统设置、自启动权限。
4. 在「大模型」里选服务并填写 API Key（加密保存在本机，不进 APK、不备份）。
5. 长按电源键试试。没反应就重启一次手机。

## 能做什么

| 类别 | 例子 | 本地直接处理 |
|---|---|---|
| 打开应用 | 打开微信 / 打开B站 / 打开留声机 | ✓（标签、拼音、别名模糊匹配） |
| 倒计时 | 倒计时十分钟 / 一个半小时后提醒我喝水 | ✓ |
| 闹钟 | 明早七点叫我 / 工作日 6 点 50 的闹钟 / 查看闹钟 | ✓ |
| 打电话 | 给妈妈打电话 / 打给 138… | ✓（联系人同音容错，有歧义会列出候选，不乱拨） |
| 导航 | 导航到西湖 / 步行去火车站 / 回家 | ✓（CoMaps 或高德，设置里选） |
| 音乐 | 播放周杰伦的晴天 / 随机播放 / 下一首 / 暂停 | ✓（留声机 Gramophone） |
| 系统开关 | 打开蓝牙 / 关闭 WLAN / 飞行模式 / 移动数据 / 深色模式 / 护眼模式 / 手电筒 / 勿扰 / 定位 / 自动旋转 / NFC | ✓（root） |
| 音量亮度 | 音量调到 30 / 声音大一点 / 屏幕暗一点 / 亮度 40% | ✓ |
| 网页搜索 | 搜索 xxx | ✓ |
| 其他 | 问问题、多步指令（"打开蓝牙然后放首歌"）、不常见说法 | 交给大模型 |

开关执行后会读回系统真实状态再报告（例如蓝牙真的开了才说"已打开"）。

## 充电控制（配合 ChgCtl 模块）

需要 KernelSU 模块 ChgCtl ≥ v1.3.0（停充上限 + 硬件级旁路供电）。主页「充电控制」进入设置页；控制中心可添加「旁路供电」磁贴（长按磁贴打开设置页）。

- **设置都保存在模块里**（`/data/adb/chgctl/config.conf`），本应用只通过模块的命令行读写，和 WebUI / 命令行的修改不会冲突。本应用从不直接写充电节点：守护进程是唯一写入者（多个写入者曾导致厂商充电驱动死锁）。
- **磁贴**：发送明确的「开 / 关」而不是「切换」（连点不会互相抵消）；状态由守护进程在变化时主动推送（带签名权限的显式广播，其他应用无法伪造），被拒绝时磁贴会自动退回真实状态。
- **自动旁路**：「亮屏时」——插着电、电量 ≥ 阈值且亮屏时旁路，灭屏满设定时间后恢复按上限充电；「插电即」——插电且电量 ≥ 阈值就旁路。本次插电期间手动关掉旁路后，自动规则不会再打开它。亮灭屏信号由本应用的前台服务提供，只在插着电且模块需要时发送。
- **状态栏旁路图标**：插着电且电池保持不充（旁路或到达上限）时显示。图标资源（由 sbicons_hyperos 覆盖成插头）和状态栏服务的调用号都在运行时按名字解析：调用号由 `IconTool` 以 root 通过 `app_process` 从系统自己的 `IStatusBarService` 读出，写入 `icon.conf` 交给守护进程；开机后和系统界面更新后自动重新生成，系统版本不符时守护进程不显示图标。设置页有「图标自检」。

## 识别屏幕文字（配合 statusbar_dt2s 模块）

需要 KernelSU 模块 statusbar_dt2s ≥ v2.0.0。**双指双击状态栏**：画面定格并标出识别到的段落，点一块复制，长按复制全部，手指划过多块一起复制，点空白处 / 返回 / 再双指双击关闭。

- 截屏：root `screencap` 原始格式（约 0.1 秒，不编码 PNG，不写文件），在助手窗口出现之前截取；广色域模式下按 Display P3 显示，定格画面和真实屏幕一致。
- 模型：PP-OCRv6 small（检测 + 识别，飞桨官方 ONNX），ONNX Runtime CPU 3 线程、关闭线程空转；截屏的同时加载模型，用完 1 分钟后释放。CI 下载模型并用和应用相同的预处理做冒烟测试。
- 检测框按行、再按段落合并（行距、行高、左对齐 / 重叠），从上到下识别，先识别好的块先能点；中文换行处不加空格，英文补空格。
- 画面只在有动画时才绘制，静止时不耗电。锁屏时不响应。触发广播受签名权限保护（root 不受限，其他应用无法伪造）。

## 不响应音频焦点的播放器

红果短剧这类应用收到短暂失去焦点（`LOSS_TRANSIENT`）后仍继续播放，助手的面板（数字助理窗口）也不会让下面的应用进入 onPause，视频声音就会被当成指令识别。

唤起时若有媒体在播放，拿到焦点的同时启动 root 小工具 `MediaTool`（它的启动时间正好留给守规矩的播放器自己暂停），找出仍在播放的应用，按下面的顺序让它停下，结果出来之前不自动发送，真的停了某个应用就丢掉这期间听到的内容（那是视频的声音）：

1. **真正的媒体会话**（会报告播放状态的）：对它的会话暂停，不行再给它的会话发暂停键。应用自己知道暂停了。
2. **没有真正的会话就静音它的播放器**：每个 AudioTrack / MediaPlayer / AAudio 都带着一个控制接口登记在音频服务里（系统强制音频焦点用的就是它），root 把正在播放的那几个的音量设为 0。红果的两个媒体会话是空壳（没有播放状态、没有元数据，忽略一切指令），靠的是这一步。不用"暂停播放器"：视频引擎按自己的时钟走画面，只停音频的话画面照走，恢复时还要卡住几秒等声音追上（红果实测如此）；静音则音画始终同步。

结束时只恢复被暂停 / 静音的那几个（按会话、按播放器编号）。说了「继续播放」就立即恢复；说了「暂停」、打开别的应用、打电话、导航、放音乐、搜索、查看闹钟时，被暂停的会话不再自动恢复，静音的一律恢复音量。设置页「诊断信息」里能看到最近一次用的是哪种方式。

## 使用

- 唤起后直接开始听（不弹键盘），说完停顿一下自动发送：「打开蓝牙」这类本机指令停顿 0.3 秒就发，提问或复杂指令按设置等待（默认 0.8 秒）；停顿后接着说话会继续等，不会把半句话发出去。开头的「嗯」「呃」和被停顿拆开的半句（「打开……蓝牙」）会自动合并处理。点麦克风按钮结束听写，点输入框改为用键盘打字。
- 语音由本应用录音，交给 Audio Input 的离线模型识别（需要 Audio Input 带 `RecognizerBridgeService` 的版本）；识别模型、语言、标点等沿用 Audio Input 里的设置。
- 「语音模型常驻内存」（默认开）：识别进程和模型一直留在内存里，说话不用重新加载。加载模型要跑几秒 CPU/NPU，常驻内存本身几乎不耗电，所以常驻反而更省电，代价是几百 MB 内存。
- 听写时音乐会暂停，指令执行完再恢复（说"暂停"就保持暂停）；8 秒没人说话自动停止听写。
- 点面板外、按返回或打开了别的应用，面板就关闭。在手机上执行了操作（开关、闹钟、打开应用…）就显示结果后自动收起；大模型只是回答、反问或执行失败时，面板停留并自动继续听你的追问（5 分钟内保留上下文），追问时音乐保持暂停，不再说话则恢复播放。

## 稳定与省电

- **没有唤醒锁、没有轮询。** 系统绑定的数字助理服务平时什么都不做；被唤起时把面板画在它自己的窗口里，关闭后释放。
- 唯一常驻的是一个什么都不做的前台服务（「保持随时可唤起」，可关）：HyperOS 会冻结后台进程，长按电源键发给被冻结进程的调用只会排队，表现为按了没反应、下次打开助手时面板才弹出来。前台服务能免于冻结；它不占 CPU，也不申请通知权限，所以不显示通知。
- root shell 按需开启，一次指令里的多条命令共用一个会话，空闲 20 秒自动关闭。
- 网络请求用系统 `HttpURLConnection`，不引入额外库；关闭面板立即取消请求。连接放回系统连接池复用；判断出这句要交给大模型时，在等待自动发送的那段时间里先建立连接（一个不带 Key 的 HEAD 请求，30 秒内最多一次），省掉 DNS + TLS 握手。
- 大模型调用的工具全部成功时直接显示读回的结果，不再等第二轮回复；只有失败或有歧义才交还给模型。需要 root 的指令在等待发送时就先启动 su。
- 对话上下文只在一轮完整结束后才记录：中途关闭面板不会留下"有工具调用、没有结果"的残缺记录（那会让之后几分钟的请求全部被服务端拒绝）。
- 应用列表只在安装/卸载后重建（`PackageManager.getChangedPackages`），联系人只在打电话时读取。
- 各家模型对"关闭思考"参数支持不一，请求被拒时自动去掉参数重试一次并记住，不会因换模型而不可用。

## HyperOS 相关的坑

- 国行 HyperOS 的长按电源键默认直接唤起小爱，只有 `long_press_power_key=launch_google_search` 时才交给默认数字助理。
- HyperOS 开机时会重新初始化语音助理，若识别服务不可用会改回小爱：因此把识别服务指向 `com.xiaomi.mibrain.speech`，并在开机后（以及助理服务被绑定时）检查一遍，被改掉就自动恢复。开机恢复依赖「自启动」，一键配置会尝试授予，失败时设置页有入口。
- 系统可能自己清空 `voice_interaction_service`（角色和 `assistant` 设置都还在）：AOSP 只会自动选用**系统**自带的助理，小爱已卸载就退回空值。这时数字助理服务被解绑，长按电源键时 SystemUI 改去把它当 Activity 启动，结果什么都不发生。前台服务监听这几个设置，被改掉 3 秒后自动恢复；打开助手时也会检查一遍。设置页「最近一次长按电源键」下面会显示上次自动修复的时间和原因。
- 从后台启动 Activity 在 HyperOS 上靠不住：前台是别的应用时，面板 Activity 会被压住，等助手自己回到前台才弹出来。所以面板直接画在数字助理会话的系统窗口里（和 Gemini / Google 助理的浮层同一机制），盖在任何应用上，不需要启动 Activity。
- 后台进程冻结：见上文「保持随时可唤起」；一键配置还会把助手加入省电白名单。设置页的「诊断信息」会列出进程是否被冻结、语音交互服务是否绑定、被停用或卸载的小米系统应用和相关日志。
- 从面板打开其他应用仍受「后台弹出界面」（MIUI app-op 10021）约束，一键配置会用 root 允许它（同时允许「锁屏显示」10020）。设置页的「最近一次长按电源键」会显示是否收到、面板是否显示。
- 戴耳机时调高音量可能被系统的安全音量限制，结果里会如实说明。
- 深色模式同时设置 AOSP 夜间模式和 HyperOS 自己的 `dark_mode_enable`；护眼模式使用 `screen_paper_mode_enabled`。

## 构建

```sh
./gradlew :app:testDebugUnitTest :app:assembleRelease
```

CI（GitHub Actions）在每次推送时跑单元测试并构建 APK。发版：Actions → Build → Run workflow 填 `release_tag`（如 `v1.0.0`），或推送 `v*` 标签。
签名用仓库 secrets 里的 keystore，按内容自动识别（secret 叫什么名字都行），没有正式签名时拒绝发版。
